# Module 1：Agent Design Patterns 学习定位

来源：Andrew Ng Agentic AI Module 1（本地双语 PDF，作为学习参考，不直接复制整份课程文本）。

## 本模块的三种设计模式

### Planning

把自然语言任务拆成有序、可执行的步骤，并由规划器决定工具、调用顺序和参数。

### Tool Use

模型判断是否需要工具；工具由开发者实现并执行，返回结果后再交给模型继续处理。

### Reflection

让智能体根据明确标准检查初稿或计划，发现问题后修订；检查不等于无条件重写。

## 对 JSON Planning 实验的补充

我之前设计的 7 步专业流程是基础版本。结合本模块后，Planning 还必须考虑：

- 运行时决定调用哪个工具，而不是把调用顺序全部写死
- 数据字段不完整或藏在自由文本中时，先做语义检索
- 遇到“便宜”“明显”等模糊词时，请求澄清或显式记录假设
- 结果为空时走分支或兜底路径
- 每一步留下 trace，检查信息是否足够再进入下一步
- 复杂任务可以拆成单一职责的规划、数据工具和回复模块

## 关键边界

Planning 不是把固定流程换成 JSON 外壳。

如果 JSON 里的步骤、工具和顺序永远固定，系统仍然更接近硬编码工作流；真正的 Agent 还要能根据输入决定是否需要某一步、调用哪个工具、是否继续检索，以及何时完成。

## 我的关键认识：Agent 设计不是业务能力本身

Agent 的 Planning、Tool Use 和 Reflection 是放大器，不是专业知识的替代品。

```text
业务实践与经验 → 知道什么值得问、什么算异常、什么结论可靠
Agent 设计模式 → 把问题拆成步骤、工具、规则和检查点
大语言模型 → 协助表达、归纳、生成候选方案
```

如果缺少金融、法律、医疗等领域的专业判断，Agent 可以做出结构漂亮的流程，却不一定做出正确、完整或可负责的结果。因此，专业 Agent 必须经过真实业务实践、领域专家校验和失败案例迭代。

本次实验中，我先提出笼统直觉，再由专业流程补充“数据口径、异常检测、待验证假设、证据边界”等关键词汇。这不是我的直觉没有价值，而是说明：

> 直觉负责发现问题，专业语言负责把问题变成可验证任务，Agent 负责执行和记录。

## 大模型已有知识，能否让 Agent 自己判断？

可以利用，但不能把“模型知道”直接等同于“模型已经验证”。大模型的训练知识可以帮助 Agent 提出专业术语、候选解释和检查项目；通过检索、计算工具、规则库和历史案例，还可以把部分业务经验接入流程。

但自检也可能继承原答案的错误，尤其是输入数据不完整、标准没有写清楚或问题需要现实责任判断时。因此更稳的分工是：

```text
人：定义目标、标准、风险阈值和升级条件
Agent：按标准执行、交叉核对、记录证据、发现疑点
人或专家：抽查高风险结果，处理标准之外的情况
```

低风险、规则明确、可交叉验证的自检可以自动化；金融决策、医疗判断、法律结论等高风险结果，不能只依赖 Agent 自检。

### 自检质量的前置条件

自检不是天然可靠的，它至少依赖三件事：

1. **标准明确**：什么算正确、异常和不可接受，必须先定义。
2. **数据可验证**：有来源、时间、口径和权限，不能只相信模型说“数据真实”。
3. **结果可交叉验证**：能用第二个来源、计算公式、规则或历史记录复核。

这些条件通常来自业务实践。Agent 可以执行已经定义好的检查，但不能凭空创造可靠的业务标准。人工的核心职责不是永远逐条检查，而是建立标准、确认数据可信度，并在高风险或无法验证时升级处理。
