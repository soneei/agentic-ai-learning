# Lab 02：JSON Planning

## 实验目标

让模型把一个真实业务任务拆成机器可解析的 JSON 计划，再由代码按步骤执行。

本实验仍然先不接真实金融数据，使用虚拟任务验证规划结构。

## 业务任务

> 根据一组公司年度经营数据，生成一份基础研究小结。

## 任务约束

计划至少包含以下步骤：

1. 读取并整理数据
2. 计算关键变化
3. 检查数据和计算结果
4. 生成研究小结
5. 标记无法由表内数据判断的内容

## 本实验要观察什么

- 模型是否能拆出合理步骤
- 每一步是否有清晰的 description
- tool 和 args 是否完整
- 下游代码能否稳定解析 JSON
- 上一步结果能否作为下一步输入

## 初步任务拆解

用户提出的步骤：

1. 阅读实际真实数据
2. 直观表述明显变化
3. 对异常数字变动提出实际推断
4. 检查前面结论是否合理准确

## 对步骤的修正

这个方向是对的，但第 3 步和第 4 步需要更精确：

- 第 1 步是数据读取与口径确认，不应默认所有数据都是真实或可直接使用。
- 第 2 步是描述性分析，只说表内确认的变化。
- 第 3 步是解释性分析，只提出“可能原因 / 待验证假设”，不能把推断写成事实。
- 第 4 步是验证与 Reflection，检查数字、计算、依据和边界。

更稳的规划顺序：

1. 明确研究问题和输出边界
2. 读取数据并确认来源、时间和口径
3. 计算关键变化并描述明显趋势
4. 检测异常变动
5. 提出带证据边界的可能解释
6. 检查数字、逻辑和是否越界
7. 生成最终小结并标注待核实事项

## 下一步

先手写这 7 步，再设计 JSON schema 和 planning prompt。
