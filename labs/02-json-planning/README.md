# Lab 02：JSON Planning

## 实验目标

让模型把一个真实业务任务拆成机器可解析的 JSON 计划，再由代码按步骤执行。

本实验仍然先不接真实金融数据，使用虚拟任务验证规划结构。

## 业务任务

> 根据一组公司年度经营数据，生成一份基础研究小结。

## 任务约束

计划至少包含以下步骤：

1. 读取并整理数据
2. 计算关键变化
3. 检查数据和计算结果
4. 生成研究小结
5. 标记无法由表内数据判断的内容

## 本实验要观察什么

- 模型是否能拆出合理步骤
- 每一步是否有清晰的 description
- tool 和 args 是否完整
- 下游代码能否稳定解析 JSON
- 上一步结果能否作为下一步输入

## 初步任务拆解

用户提出的步骤：

1. 阅读实际真实数据
2. 直观表述明显变化
3. 对异常数字变动提出实际推断
4. 检查前面结论是否合理准确

## 对步骤的修正

这个方向是对的，但第 3 步和第 4 步需要更精确：

- 第 1 步是数据读取与口径确认，不应默认所有数据都是真实或可直接使用。
- 第 2 步是描述性分析，只说表内确认的变化。
- 第 3 步是解释性分析，只提出“可能原因 / 待验证假设”，不能把推断写成事实。
- 第 4 步是验证与 Reflection，检查数字、计算、依据和边界。

更稳的规划顺序：

1. 明确研究问题和输出边界
2. 读取数据并确认来源、时间和口径
3. 计算关键变化并描述明显趋势
4. 检测异常变动
5. 提出带证据边界的可能解释
6. 检查数字、逻辑和是否越界
7. 生成最终小结并标注待核实事项

## 分支判断

固定步骤还不够，Agent 还要根据数据状态决定下一步：

```text
数据缺失
→ 回到原始数据源补充
→ 若原始数据也没有，标记为无法判断

口径模糊
→ 先向用户澄清
→ 澄清前暂停计算

结果异常
→ 进入核查流程
→ 复核原始数据、计算公式和输入口径
```

这里的关键边界是：

> 补充数据不等于猜测数据。原始数据也没有时，必须停止越界推断。

本轮分支计划见：`plan-with-branches.json`。

## 最小执行器

`executor.py` 不调用大语言模型，只负责验证 JSON Planning 的分支规则。

运行：

```bash
python3 executor.py
python3 -m unittest discover -p "test_*.py"
```

测试场景：

- 数据缺失且原始源可补充 → `fetch_from_source`
- 口径模糊 → `ask_for_clarification`
- 结果异常 → `verify_source_and_calculation`
- 原始数据也缺失 → `stop_without_guessing`
- 数据正常 → `generate_hypotheses`

本实验先把“分支是否正确”与“模型是否聪明”分开，便于定位问题。

## 执行器从输入到输出的完整流程

```text
1. 创建 Scenario
   输入场景名称、缺失字段、原始数据可用性、口径状态和结果状态

2. 调用 choose_path(scenario)
   执行器按优先顺序检查各类状态

3. 检查数据缺失
   有缺失且原始源可用 → fetch_from_source
   有缺失且原始源也没有 → stop_without_guessing

4. 检查口径是否模糊
   模糊 → ask_for_clarification，并暂停后续计算

5. 检查结果是否异常
   异常 → verify_source_and_calculation

6. 如果以上问题都不存在
   → generate_hypotheses，继续提出带边界的可能解释

7. 返回结构化字典
   包含 status、next_step、message

8. run_demo 逐个运行五种场景并打印结果
```

核心链路：

```text
结构化输入 → 按优先级判断 → 选择路径 → 结构化输出
```

## 它距离真正的 Agent 还缺少什么

当前执行器是一个有价值的**确定性规则执行器**，但还不是完整的 Agent。它目前只能根据已经整理好的布尔状态，在固定分支中选择路径。

主要缺口：

1. **自然语言理解**：还不能从用户问题和原始材料中自主识别任务、字段和意图。
2. **运行时规划**：步骤和判断规则已经写死，不能根据新情况动态调整计划。
3. **工具执行**：`fetch_from_source`、`verify_source_and_calculation` 等目前只是字符串，还没有真正调用数据源、计算器或检索工具。
4. **观察—行动循环**：执行一步后还不会读取工具结果、更新状态，再决定下一步。
5. **失败恢复**：工具失败、数据冲突或多次补充仍为空时，还没有重试、换工具或升级人工的机制。
6. **停止条件与记忆**：还没有根据证据充分程度判断何时结束，也没有保存跨步骤的上下文和 trace。
7. **质量评估**：还没有自动检查最终结果是否满足 criteria。

因此，更准确的定位是：

```text
当前执行器 = Agent 的规则与分支底座
完整 Agent = 理解目标 + 规划 + 调用工具 + 观察结果 + 调整行动 + 质量检查
```

重要边界：完整 Agent 不一定必须依赖大语言模型；但如果要处理自然语言和开放任务，通常需要模型作为规划与理解组件。
