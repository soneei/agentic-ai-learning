# Reflection 检查清单

对 Direct Generation 的每条输出，使用同一套标准检查。

## 0. 对象识别（Object identification）

> 在检查具体标准之前，先回答总问题：**What kind of output are we reviewing?**（我们正在检查什么类型的输出？）

- [ ] 输出对象已明确：数据图表 / 日程卡 / 研究报告 / 代码输出 / 其他
- [ ] 已明确这类对象的使用目的：读者要理解、比较、执行还是决策？
- [ ] 已选择与对象匹配的检查项，而不是机械套用所有标准
- [ ] 若对象无法识别：先澄清对象和用途，再开始 Reflection

对象与重点示例：

| 输出对象 | 重点检查项 |
|---|---|
| 数据图表 | 图表类型、单位、时间范围、图例、数据来源 |
| 日程卡 | 日期、时间、任务、上下文、完成标准 |
| 研究报告 | 证据、事实与推测、边界、待核查项 |
| 代码输出 | 测试、错误处理、可复现性、输入输出边界 |

## 0.1 图表输出的可执行检查（课程小测试）

> 使用方式：每一项都回答“通过 / 不通过”，不只写“看起来不错”。发现“不通过”时，必须写出问题和改进动作。

### A. Readability（可读性）

- [ ] 图例、坐标轴、标签和文字是否看得清？
- [ ] 数据是否拥挤、重叠或堆叠到难以读取？
- [ ] 读者是否能在几秒内找到需要比较的数据？
- [ ] **若不通过：** 用一句话指出具体阅读障碍：`The chart is difficult to read because ...`

### B. Clarity（清晰度）

- [ ] 图表类型是否适合这个问题？
- [ ] 2024 和 2025 等比较对象是否清楚区分？
- [ ] 标题是否说明了比较的对象、范围和时间？
- [ ] 图表是否表达了正确的比较关系，而不是制造误解？
- [ ] **若不通过：** 写出一个具体改进动作：`Please improve it by ...`

### C. Completeness（完整性）

- [ ] 单位是否明确，例如 `items` / `units`？
- [ ] 时间范围是否明确，例如 `Q1 2024` 和 `Q1 2025`？
- [ ] 数据来源或数据边界是否说明？
- [ ] 图例是否覆盖了所有必要系列？
- [ ] 是否缺少理解结论所必需的背景信息？
- [ ] **若不通过：** 写明缺少什么，以及应该补在哪里。

### D. 生成可执行 Reflection

- [ ] 先写具体问题，不使用 `It looks bad`、`Make it better` 这类模糊反馈。
- [ ] 再写改进动作，说明要改变什么以及如何改变。
- [ ] 改进后重新生成 V2，并再次执行 A–C 检查。

模板：

```text
The chart is difficult to read because [specific problem].
Please improve it by [improvement action].
Also make sure the chart includes [missing context],
including the unit, time range, and data source when needed.
```

## 1. 数字准确性

- 原表数字是否抄对？
- 增长率计算是否正确？
- 方向是否判断正确？

## 2. 依据可追溯

- 每条结论能否回到表内找到数字？
- 是否把表外信息当成已知事实？

## 3. 事实与推论分开

- 哪些是表内事实？
- 哪些是基于数据的推导？
- 推导是否使用了“说明”“可能”“无法判断”等边界语言？

## 4. 越界检查

- 是否虚构行业地位、竞争格局、估值或市场信息？
- 是否给出买卖建议？
- 是否把债务增加直接等同于风险恶化？

## 5. 遗漏检查

- 是否同时看到了增长和增速变化？
- 是否同时看到了经营现金流增长与负债增加？
- 是否指出数据缺少同比/环比标签？

## 6. 按对象选择合格结论

只有先完成对象识别，再按对象选择对应检查项，最后确认所有适用项通过，才算合格。

- 数据图表：数字/视觉表达正确、单位和时间范围完整、比较关系清楚
- 日程卡：日期和任务上下文完整、时间顺序清楚、完成标准可执行
- 研究报告：依据可追溯、事实与推论分开、边界和待核查项明确
- 代码输出：测试通过、错误处理明确、输入输出边界清楚、结果可复现

如果发现“不适用”，要记录原因；不能把“不适用”误写成“已通过”。
